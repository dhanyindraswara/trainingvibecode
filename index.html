01

Fitur Claude

Chat

Halaman kosong yang bisa menjawab balik.

  • Teman berpikir: menguji rencana sebelum kita keluarkan anggarannya.
  • Menyusun draf: proposal, jawaban tender, berita acara serah terima, email yang sulit ditulis.
  • Analisis: tempel tabel, kontrak, atau spesifikasi, lalu cecar isinya.
  • Pencarian web dan upload file tersedia — tapi hanya untuk yang kita berikan sendiri.
Batasnya

Chat tidak punya akses tetap ke komputer atau drive kita. Itu memang dirancang begitu demi keamanan. Kalau butuh akses, kita pindah fitur.

Kebiasaan yang paling terasa hasilnya

Sebutkan bentuk jawabannya

# lemah Tolong buatkan laporan proyek. # kuat Buat laporan proyek untuk Direktur Proyek. 4 bagian: progres, yang meleset, keputusan yang aku butuhkan darinya, rencana 2 minggu ke depan. Maksimal 250 kata. Nada lugas. Beliau tidak suka kalimat yang berputar.

Pembaca, struktur, panjang, nada. Empat batasan ini mengubah jawaban umum jadi jawaban yang bisa dipakai. Sesederhana itu keahliannya.

05

Fitur Claude

Cowork

Claude yang diberi izin menyentuh file kita yang sebenarnya.

  • Kita tunjukkan foldernya. Dia membaca, meng-edit, dan membuat file di situ — tanpa upload, tanpa salin-tempel.
  • Tersambung ke aplikasi yang sudah kita pakai: Drive, Gmail, Slack, SharePoint, Notion, Calendar.
  • Pekerjaan bertahap dituntaskan sampai jadi hasil nyata, dengan rujukan balik ke sumbernya.
  • Jalan di aplikasi desktop; versi web dan mobile masih beta. Kita bisa mengarahkannya dari HP.
Disiplin

Beri dia folder yang terbatas, jangan seluruh drive. Sama seperti kita mengatur akses kontraktor baru ke area proyek.

Chat vs Cowork, satu kalimat saja

Chat memberi tahu caranya mengerjakan.
Cowork mengerjakannya.

Contoh nyata. Satu folder berisi 180 nota dan formulir reimbursement hasil scan. Chat bisa menjelaskan prosedur yang baik. Cowork membuka satu per satu, membaca nominalnya, menyusun spreadsheet-nya, menandai empat yang tidak cocok, lalu meninggalkan hasilnya di folder itu.

06

Fitur Claude

Claude Code

Tempat kerja yang akan membangun aplikasi kita siang nanti.

  • Bekerja di seluruh repository, bukan satu file — dia membaca konteksnya dulu sebelum menulis.
  • Menjalankan perintah, membaca pesan errornya, memperbaiki, lalu mencoba lagi dalam satu putaran.
  • Ada di browser lewat claude.ai/code — itu yang kita pakai hari ini, tanpa memasang apa pun. Tersedia juga di terminal, VS Code / JetBrains, dan aplikasi desktop.
  • Bisa commit, membuat branch, dan membuka pull request langsung ke GitHub.
Aturan hari ini

Claude Code tempat kita menambah menu. Claude Design tempat kita memutuskan menu. Jangan dibalik.

Sesi kerjanya kira-kira begini
kamu › Tambahkan halaman ketersediaan unit. Bisa disaring per cluster, tipe, dan status. Ambil dari tabel units. claude › membaca skema… 3 file menulis app/units/page.tsx menulis components/UnitFilter.tsx build… gagal memperbaiki type error di props build… berhasil ▸ siap di /units

Kita memeriksa perubahannya. Peran kita penyetuju, bukan juru ketik.

07

Fitur Claude

Claude Design

Ceritakan, klik, lalu perdebatkan — sebelum ada yang menulis kode.

  • Dari kalimat jadi prototype: layar, alur, slide, dan lembar ringkas yang benar-benar bisa diklik.
  • Perbaikan lewat percakapan, komentar di tempat, edit langsung, atau slider yang dibuatkan Claude.
  • Bisa mempelajari design system kita — warna, huruf, dan komponen dipakai otomatis.
  • Hasilnya diserahkan mulus ke Claude Code untuk dibangun.
Kenapa penting

Berdebat soal layar yang bisa dilihat memakan waktu menit. Berdebat soal layar yang sudah terlanjur dibangun memakan waktu hari.

Ikuti uangnya

Kemampuannya sudah mirip. Harganya belum.

Empat model tertutup terdepan sekarang hanya terpaut empat poin di soal sains tingkat doktoral. Tapi di tagihan, jaraknya sama sekali tidak empat poin.

  • Model terbuka dengan harga jauh lebih murah sekarang benar-benar cukup untuk sebagian besar pekerjaan rutin.
  • Model kelas atas baru terasa layak harganya di 10% pekerjaan yang sulit — tugas panjang, konteks besar, masalah yang kabur.
  • Pola yang menang adalah routing bertingkat: pakai yang murah dulu, naik hanya kalau gagal.
Rancang begitu

Taruh pilihan model di satu config value. Kalau harga atau juaranya berganti — dan itu terjadi dua kali setahun — kita cukup mengubah satu baris.

Jadi, kenapa Claude hari ini?

Karena pekerjaannya, bukan karena mereknya.

Alasan 01

Kita sedang menulis kode

Tugas hari ini adalah aplikasi multi-file yang dibangun dalam sekali duduk. Di kategori inilah jaraknya paling lebar dan paling konsisten.

Alasan 02

Tempat kerjanya nyambung

PRD, prototype, dan implementasi tinggal di satu keluarga produk. Makin sedikit serah terima, makin sedikit tempat untuk kehilangan alur.

Alasan 03

Ingatannya panjang

Pembangunan delapan jam butuh alat yang masih ingat keputusan yang kita ambil pukul 09.30.

Dan jujur saja

Untuk membuat gambar, nanti siang kita justru memanggil OpenAI, karena di situlah kekuatannya. Pakai alat terbaik untuk tiap pekerjaan. Setia pada satu vendor bukan strategi — yang strategi adalah gampang diganti.

Tahap · Claude Web

Tulis PRD-nya

  • Lampirkan contoh PRD dulu. Model meniru bentuk yang kita tunjukkan. Tunjukkan yang bagus, hasilnya bagus.
  • Sebutkan stack-nya di dalam PRD. Next.js, MySQL, MinIO, Docker — ditulis, bukan diasumsikan.
  • Dokumen ini jadi batasan untuk Claude Design. Design tidak boleh mengarang scope yang tidak ada di sini.

Tahap · Claude Code

Bangun

Praktik · Database & Storage

Nempel kredensial di Claude Code

  • 1 · Tulis .env.local — di root project. Salin template di kanan, ganti [n] dengan nomor kelompokmu.
  • 2 · Isi kredensial — password MySQL dan secret key MinIO dari lembar ACCESS kelompokmu. Diketik langsung — jangan difoto, jangan dikirim ke grup chat.

  • 4 · Prompt Claude Code — pakai prompt di kanan bawah. Biarkan Claude yang menulis kode koneksinya; kita yang pegang kredensialnya.

Tahap · Integrasi

Pasang kecerdasannya

  • RAG — dokumen kita dijawab dengan sumbernya. Tanpa sumber, tidak ada kepercayaan.
  • Chatbot — pencarian yang sama, dibungkus percakapan, lengkap dengan riwayat.
  • Gambar → OpenAI — pembuatan dan pembacaan gambar dilempar ke OpenAI, karena di situ kekuatannya.
  • Semua kunci di sisi server. Kunci di kode browser sama saja dengan kunci yang ditempel di internet.
Bikin gampang ditukar

Satu config value menentukan penyedianya. Saat harganya bergerak kuartal depan, kita mengganti satu baris — bukan arsitektur.

RAG dalam tujuh langkah, tanpa mistis
  • 1 · Upload → file masuk MinIO, row-nya masuk MySQL
  • 2 · Extract → tarik teks keluar dari PDF
  • 3 · Chunk → 500–1.000 token, dengan sedikit overlap
  • 4 · Embed → tiap chunk diubah jadi vektor
  • 5 · Store → simpan vektor + link balik ke sumbernya
  • 6 · Retrieve → pertanyaan masuk, chunk paling cocok keluar
  • 7 · Answer → chunk + pertanyaan ke model, keluar jawaban bersumber

Chunking yang buruk tidak bisa ditolong model yang lebih pintar. Kalau jawabannya sering meleset, periksa langkah 3 dulu — bukan langsung naikkan modelnya.

Commit = save point

Satu layar jadi · satu commit
Aturan keras

Sebelum push pertama, buka .gitignore dan pastikan ada baris .env. Kredensial yang sudah ter-push tetap tersimpan di riwayat walau nanti dihapus.

Prompt commit — tempel apa adanya
Layar daftar unit sudah jalan. Commit dengan pesan yang jelas, lalu push.

Kapan commit? Setiap satu layar berhasil dibuka di browser. Bukan setiap satu jam, bukan sekali di akhir hari. Commit yang jalan itu tempat kita pulang saat percobaan berikutnya gagal.
